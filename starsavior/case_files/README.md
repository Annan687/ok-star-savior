# 案件檔案整合核心

來源：使用者提供的 StarSavior 助手 v1.4.1（原資料夾名為 v1.4），2026-09-18 匯入。保留數字／HUD／畫面模板、Python 計分驗證、新版 CoreHost 與 v1.2 RouteSearch 搜尋器；原生二進位未重新編譯，雜湊記於 `source.json`。同資料夾提供的 C# 原始碼存於 `native/`。

OKSS 入口是 `starsavior.case_task.CaseFilesTask`，由框架的「任務」頁啟動；不啟動原 Tkinter GUI 或其 EXE。`solver.py`、`live_core.py`、`observations.py`、`session.py` 改用套件相對匯入，不改全域搜尋路徑。

整合差異：

- 移除原程式 F8 偵測及載入時的程序 DPI 設定，由 OKSS 負責。
- `FrameworkStopEvent` 連接 OK 共用啟停（預設 F9）、任務停止／暫停、程式退出。即時倒數任務遇到暫停就結束本次操作；取消一旦成立便保持，不續用過期盤面。
- 正常結算才允許自動重開，局間仍檢查焦點、視窗位置／大小及取消；異常不重開。
- 每局紀錄由外層指定到 `runs/case-files/`，回報到框架任務資訊；未辨識的結算分數顯示未確認。
- finally 清理互相獨立：放開滑鼠、關閉搜尋器、關閉紀錄檔。舊搜尋器模式仍保留新版觀測與核心交叉驗證。

保留的限制：原來的前台擷取與輸入、1600×900 遊戲內容的視窗模式（包含原模板對應的外框）。使用者需先停在案件檔案首頁；自動重開也接受 RESULT。此模組不使用日課的 OCR 導航，不自動領獎，不承諾其他尺寸、背景操作或固定高分。v1.4.1 快速拖曳維持原版設定，整合後仍待真實遊戲驗證。

私有全畫面樣本、原工具執行紀錄、設定與啟動器未匯入。日課與案件檔案使用同一框架執行器排隊，不建立額外的遊戲操作執行緒。
